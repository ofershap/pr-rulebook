PR Rulebook

Generic AI reviewers know best practices. Your team's real rules are buried in old PR comments. PR Rulebook digs them out.

View on GitHub Quick start

The problem

Your team always rejects fetches outside the data layer. Wants domain errors, not thrown strings. Refuses snapshots for business logic. None of that is written down - it lives in thousands of accepted review comments you already paid for.

AI code reviewers can't see any of it. They review against public best practices and miss the conventions your team actually enforces.

What it does

  • Scans your merged pull requests from the last 3-6 months via the GitHub API.
  • Finds recurring human review feedback that was followed by a code change (bot comments excluded).
  • Clusters similar feedback locally and ranks candidate rules by repetition, acceptance signal, and distinct reviewers.
  • Compiles a rulebook where every rule carries evidence links, occurrence counts, and a confidence score.
  • A human approves every rule before it reaches your agents. Nothing is silently enforced.

Why it's different

Your rules, not the internet's

Rules come from your own merged-PR history, with links to the exact comments that support each one.

Local-first

Runs on your machine. There is no PR Rulebook server. Nothing leaves except GitHub API calls with a read-only token.

Human-approved

Output is a review queue, not an auto-applied policy. You approve, rewrite, or reject each rule first.

Exports to your tools

Cursor rules, Claude Code instructions, CodeRabbit config, or plain JSON for your own pipeline.

Quick start

Node 20+. Takes about two minutes. The npm package is not published yet - run from source:

git clone https://github.com/ofershap/pr-rulebook.git
cd pr-rulebook
npm install
npm run build

export GITHUB_TOKEN=github_pat_...   # read-only repository access
node dist/cli.js --repo your-org/your-repo --months 6 --out REVIEW_RULES.md

Export formats: cursor, claude, coderabbit, json.
